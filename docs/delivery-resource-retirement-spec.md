# Delivery resource retirement with effects retained

Planning-ready Goal Spec, AL39. Product gap remains open: no product behavior has been implemented by this documentation Task. A later native Goal must authorize implementation. This Spec selects one bounded path; it does not authorize changes to AL25 or start its replacement.

## Goal and first scope

Let a coordinator retire the resource ownership of an already absent, started, stopped interactive local Epic delivery, retaining its actual source and every unresolved effect. Reuse AL14 report retirement's source/absence/retention model through an explicit mode on existing `workflow execute retire`. Resource closure must never mean effect resolution, successful delivery, permission confirmation, replay, automatic replacement start or source cleanup.

The first slice supports structured `local_epic_integration` deliveries with a native start, bound provider/session, preserved active coordinator stop, verifiable Task preparation and present source worktree. Support both receipt and legacy starts without changing their original permission claims. The owner pane must already be absent. No live-owner close, same-owner continuation, generic effect audit, new approval system or automatic backup is included. Other retirement paths retain their existing behavior.

A genuine unknown external effect remains unknown even after resources are retired. Any later action that depends on that effect remains blocked until separately observed through a legitimate supported path. Independent authorized development can proceed in a fresh Task; it must not assume a remote write failed, repeat the refused action or race an unresolved external operation. Queue release is no proof of external quiescence.

## Proposed public contract

Add one opt-in flag to the existing command (`--retain-effects` does not exist in the inspected CLI):

```text
ply workflow execute retire RUN_ID --retain-effects \
  --observer 'actual coordinator' --reason 'resource ownership only' --format json
```

`--retain-effects` selects the new resource-only mode. Run ID plus this flag and existing observer/reason are the complete operator input. Bind and validate the native session, all stop/evidence bytes, preparation and observed source internally; no manual session or hash-copy gate is added. Run from the containing workspace outside the Task source. The existing `workflow run retire` alias shares parsing; it must reject the new mode for report Runs rather than silently ignoring it. Default retire, report retirement, resolve-stop and provider audits keep their semantics. No `--force`, permission-confirmation or free-text effect downgrade is introduced.

Expose an additive `delivery_status.resource_retirement` object on `execute show` and retire readback. Its fields are `mode` (`retain_effects` or null), `state` (`not_retired`, `recorded_pending_release`, `retired`), `native_session`, `active_stop`, `source`, `retained_effects`, `retirement` (event FileBinding or null), `retained_observations` (ordered append-only observation bindings), `queue_disposition`, `next_action`. Before recording, `source` is null; after recording it describes the latest retained observation, with earlier observations accessible through their immutable bindings. Plain show reads recorded evidence and queue disposition; it computes no fresh source digest and performs no process inspection. Recorded observations supply no permission or fresh liveness grant. Old records remain readable with no invented new source/effect evidence.

After successful resource retirement, delivery phase remains `stopped`; `active_stop` and all original stop events remain unchanged. The object shows the hash-bound retained source/effects, event binding and exact preparation disposition. Final delivery remains `not_delivered`; existing technical evidence and human judgments remain history and acquire no new pass/current qualification. Readback must prominently say: “Resources retired; original effects retained, including uncertainty. No delivery or replay. Fresh Task mandate required.” Any later verify, integrate, owner continuation or callback is rejected as `owner_retired`; read-only show remains available.

On first recording with partial/unknown effects, emit WARN to stderr containing Run, original status, retained record and source digest, matching AL14. JSON stdout remains parseable. Show and completed retries expose the same caution and immutable bindings without refreshing historical evidence. A pending-release retry that appends a new retained observation emits the same WARN for retained partial/unknown effects and identifies that new binding; the original receipt stays unchanged.

## Operation and recovery

1. Validate explicit mode/observer/reason and supported Run mode under native workflow serialization. Check bound request, native start facts, provider/session, active stop and exact preparation/plan/source identity. Reject any native terminal (including blocked terminal), completed delivery, ownership release or human integration. No terminal history is rewritten.
2. **Native attempts:** reject `Delivery.Attempt` unless absent or `recorded`; reject any incomplete/unknown owner-resume phase, including tab/prompt attempts. Use the stricter [deliveryQuotaAttemptGuard](../internal/taskrun/delivery_quota_reconcile.go:131) approach for resume completion. A partial/unknown stop alone does not block this resource mode; a native operation with an unobserved outcome does. Never convert an attempt into an effect-retention annotation.
3. Validate every unresolved stop's bound bytes, provider and session against this Run. Retain each FileBinding, original effect/action and evidence binding, including prior quota/capacity annotations as history. Different-session/damaged stop history blocks. Do not clear an earlier partial stop because a later stop says `not_started`.
4. Observe actual source using the AL14 helper extracted into shared code with neutral diagnostics, without imposing clean/original-OID requirements post-start. Reuse the retained-source shape; keep existing report fields compatible. Source includes dirty/untracked/unique work at its original path; no commit, reset, patch application or worktree deletion is performed.
5. **Writer absence:** use `taskWriters.cleanup()` once per fresh observation pass. Require bound pane and managed agent positively absent, complete unambiguous inventories with no Task/session writer, and complete local observation with no remaining writer. Live pane refuses before local inspection; unknown/denied inspection refuses without automatic retry. Never call `deliveryRetireClosePane`, send input or invoke a provider in this mode. Record the existing process-method limitation and fresh inventory timestamp/hashes separately from cached historical transport.
6. Re-observe source and require exact equality to step 4, including identity/digest. Source change within the observation blocks this call before recording/release. A later ordinary retry may observe a stable changed source as described below. No claim is made about stability after this bounded observation or arbitrary external effects.
7. Append one native `owner_retirement` event, extending `DeliveryRetirement` with an optional mode plus internally bound provider/session, active stop, all retained delivery effects/source and exact preparation identity. Preserve the existing event reader and callback closure mechanism. Existing report field names may remain for compatibility; new delivery evidence must have explicit delivery semantics. Durably recover an event written before state indexing using the native event recovery path; add a bounded fault test here. Mark stopped, then release only the bound preparation.
8. Queue release validates exact preparation identity, target and disposition. Already `released` or `advanced` is observed completion of this resource boundary; foreign current/pending entries and queue revision remain unchanged. If it is current, freshly repeat steps 1–6 against current facts before release. Require stability within these new source/guard observations, not equality to an older receipt's source. If source or valid stop/effect bindings have settled since the previous observation, append a retained observation bound to the original retirement event and prior observation before releasing. Preserve original and new source/effect facts separately; this is no effect resolution. Any within-call drift, native pending attempt, corrupted/foreign binding or unknown/present writer blocks this dependent release. Recheck guard/stop bindings before committing the observation and queue step; a race returns pending release. Queue CAS conflict returns a diagnosis; it must never advance a successor. A recorded event with incomplete release is `recorded_pending_release`, not completed retirement.

**Lost reply and settled changes:** identical Run/mode/observer/reason recovers the same retirement event and remaining queue step. Once the exact preparation is closed, retry/show requires no new writer inspection or source mutation to read historical completion. A recorded receipt is historical, not fresh writer absence proof for an outstanding release. Conflicting mode/observer/reason is rejected; existing default-path receipts cannot be upgraded into this mode.

For `recorded_pending_release`, the same ordinary command is the supported way forward after later settled local changes. It revalidates native session/request/start/terminal/preparation, all current stop/evidence bytes and attempts, then observes current source twice around fresh writer absence. A changed OID or dirty file relative to the old receipt alone is allowed; changing ref/common-dir/preparation identity is not. Drift between the current call's observations or unknown writers/attempts blocks that call. When current facts are stable, preserve a new hash-bound retained observation before release if source or retained stop/effect bindings differ. Its native record binds Run/request/session, exact preparation, original retirement event, prior observation, current source/effects and fresh absence evidence. Extend existing event persistence/recovery to recognize this append-only observation event, not another retirement, private edit, permission decision or replacement start. Recovery recognizes an already persisted observation before considering another; unchanged retained facts reuse it, while an outstanding release still requires fresh absence. Lost replies cannot duplicate observations or releases. Record source/status changes truthfully without claiming they were harmless external effects. Every earlier receipt, unknown effect and refused action remains history. New valid same-owner stops are retained too; corrupt or foreign stop bindings remain hard failures. No new CLI selector, effect-clearance flag or event erasure is required.

**Fresh mandate:** retirement starts nothing. A coordinator may separately register/select a fresh Task with its own source, permissions and delivery agreement. Useful old work may be explicitly reviewed and copied under that mandate. It inherits no acceptance, quota clearance, review, QA, permission or effect assumptions. This mode does not extend the pre-work-only `backup-goal` path. AL25 inspection/retirement after implementation would be a separately selected root-owned action, conditional on supported observations; this Spec neither performs nor promises it.

## Acceptance criteria for the implementation Goal

- A1: The explicit command and additive show object implement exactly the selected local Epic/post-start/absent-owner scope. Legacy/default/report behavior remains compatible. Unsupported modes and corrupt/foreign internal bindings refuse before resource effects; operator supplies no session/stop/source selectors and ordinary show does no fresh source hashing.
- A2: S01/S02 preserve source identity/content, every stop/evidence/annotation and original effect status. Stopped/retired resources never become delivered, resolved, replayable or permission-confirmed. Warning and JSON readback distinguish these facts.
- A3: S03–S06/S08 block before event/release; no new mode pane-close, input, provider start, source deletion or unauthorized process inspection occurs. Unknown observations remain unknown with an actionable diagnostic.
- A4: S07/S09–S11 release exactly the owned preparation once, recover durable receipts after lost replies, preserve foreign queue order/revision, and show pending release truthfully. Completed historical retry does not refresh evidence. Pending-release retry after settled source changes must progress through new retained observations without changing old bytes or bypassing current guards.
- A5: Every late owner callback, verify/integrate and resume refuses retired ownership. Reading history remains possible, retaining pre-existing tests/reviews/QA as historical facts. Fresh work requires an independent mandate.
- A6: Focused modeled positives and actual public CLI checks are separately reported with raw outcomes and independent semantic review. No modeled absence is reported as OS permission, no denied historical action is replayed, and no full provider journey is claimed.
