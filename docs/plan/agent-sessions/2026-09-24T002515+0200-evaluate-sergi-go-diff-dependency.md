### API, behavior, closure, and qualification

The single production package implements Google's diff-match-patch model:
text/rune differencing, semantic/efficiency cleanup, fuzzy matching, patch
construction/application, delta encoding, and patch-text parsing. `New`
returns a mutable configuration object controlling timeout, edit cost, match
distance/threshold, patch threshold/margin, and match bit width. `PatchMake`
accepts the documented one-, two-, and three-argument forms for diffs,
text/text, and text/diffs. Its textual patches use unified-diff-like headers
but rolling context rather than traditional Unidiff semantics.

String inputs are caller-owned and immutable. `DiffMainRunes` reads caller
rune slices and returns new diff values. Cleanup methods deliberately mutate
the supplied `[]Diff` backing data; `PatchAddPadding` and `PatchSplitMax`
mutate patch slices, while `PatchApply` first deep-copies patches and returns a
new string/results slice. Methods allocate per call and retain no resource, so
there is no cleanup lifecycle. The same instance only reads its configuration
during a call and is suitable for concurrent calls while callers do not
concurrently mutate configuration or shared mutable slices. Output is
algorithmically deterministic when timeout is disabled; the default wall-clock
deadline can change the chosen partial result. `DiffFromDelta` and
`PatchFromText` return parse errors, while invalid `PatchMake` dynamic types,
invalid indexes, and internal impossible rune states retain panic boundaries.
