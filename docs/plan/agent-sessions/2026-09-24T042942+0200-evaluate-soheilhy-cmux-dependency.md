### Source, API, and ordinary behavior

Cmux accepts connections from a caller-owned root `net.Listener`, sniffs
buffered bytes, and dispatches each accepted connection to the first ordered
matching child listener. The public boundary includes `CMux`, `Matcher`,
`MatchWriter`, `ErrorHandler`, `ErrNotMatched`, `ErrListenerClosed`, `New`,
`MuxConn`, generic prefix/any matchers, HTTP/1 and HTTP/2 matchers, TLS
matching, and HTTP/2 settings/header matchers. V0.1.5 adds `ErrServerClosed`
and `CMux.Close`, so it is not API-identical to selected v0.1.4.

The mux owns accepted connections, buffered sniff data, and child queues; the
caller continues owning the root listener. Serve creates per-connection
goroutines, drains or closes queued connections when it exits, and delegates
accept errors to its configured handler. V0.1.5 `Close` closes internal done
channels but does not itself close the root listener. Matchers and settings
are expected to be configured before concurrent serving; general mutable
configuration is not synchronized. Sniffed bytes are replayed, matcher input
is read through the owned connection buffer, and match writers may emit HTTP/2
settings. Prefix constructor input is copied into matcher state. Given the
same bytes and matcher order, routing is deterministic apart from normal
network, scheduling, and error-handler timing.

HTTP/1 matching bounds its header read at 4,096 bytes; HTTP/2 parses frames
and HPACK headers; TLS uses prefix matching. Ordinary errors include unmatched
connections and closed listeners; parsing or matching failures return false,
and the handler controls whether accept errors stop serving. Static review of
all tests found only small loopback or `net.Pipe` fixtures with bounded
deadlines. The certificate generator writes only inside the contained release
copy and cleans up. No fuzz, stress, malformed, adversarial, escape-sequence,
oversized, deeply nested, cyclic, resource-exhaustion, security, or exploit
fixture was created or run.
